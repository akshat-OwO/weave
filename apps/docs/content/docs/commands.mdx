## `create`

Create a new VM or restart a stopped VM:

```sh
weave create <name> [--cpus <count>] [--memory <GiB>] [--ttl <duration>] [--template <name-or-path>]
```

The default TTL is 10 minutes. A template can only be supplied when creating a new VM, not when restarting an existing one. For backward compatibility, `create` continues to restart stopped VMs and can update their CPU or memory configuration; use `start` when no configuration change is intended.

## `start`

Start an existing stopped VM without changing its configuration or virtual disk:

```sh
weave start <name> [--ttl <duration>]
```

Starting assigns a new 10-minute TTL by default. Set `--ttl` to choose another duration. The command reports an error when the VM does not exist, is already running, or is in another non-stopped lifecycle state.

Before starting, Weave verifies that the persisted Lima configuration has no host-directory mounts and reasserts `--mount-none`. If the configuration was edited externally to add a mount, `start` refuses to boot it and directs you to `weave create <name>`, which safely removes mounts while preserving its CPU, memory, and disk.

## `ls`

List VMs, their status, and remaining TTL:

```sh
weave ls
```

`weave list` is an alias.

## `ssh`

Open an interactive shell in a running VM:

```sh
weave ssh <name>
```

## `shell`

Run a command in a running VM:

```sh
weave shell <name> "<command>"
```

## `stop`

Stop a VM without deleting it:

```sh
weave stop <name>
```

## `kill`

Permanently delete a VM and its virtual disk:

```sh
weave kill <name>
```

<Callout type="warn" title="Permanent deletion">
  `weave kill` removes the VM and its guest data. Use `weave stop` when you want
  to keep the virtual disk for later.
</Callout>

## `upgrade`

Upgrade the installed CLI to the newest compatible stable release:

```sh
weave upgrade
```

For versions before 1.0, Weave stays within the installed minor version. For versions 1.0 and later, it stays within the installed major version. The command never downgrades a newer installation and clearly reports when no update is needed.

The update is downloaded before the installed executable is touched. Weave stages the new executable beside the existing one and replaces it atomically, so a download or replacement failure leaves the working binary in place. An installation under a privileged directory such as `/usr/local/bin` may prompt for administrator access.

## `uninstall`

Stop every running Weave-managed VM and remove the installed CLI:

```sh
weave uninstall
```

Weave discovers VMs from its dedicated Lima state directory. If any running VM cannot be stopped, uninstall aborts and leaves the CLI installed so you can resolve the failure and retry. Removing a CLI from a privileged directory may prompt for administrator access.

<Callout type="info" title="Persistent data is retained">
  Uninstall removes only the `weave` executable. It retains the bundled Lima
  runtime, configuration, VM disks, and guest user data under `~/weave` on macOS
  and Linux or `%APPDATA%\weave` on Windows. Weave never deletes that directory
  during uninstall. After confirming that no VM data is needed, you may remove
  it manually.
</Callout>

Run `weave <command> --help` for command-specific examples and options.
